# 主动唤醒与工作接续实施计划

按 subagent-driven-development 分工，在维护分支上以 Node.js 24、SQLite、现有队列及安卓 WebView 实现。依据 [已确认的设计](../specs/2026-11-25-proactive-work.md)。保留旧提醒和桌面回执。

1. 候选生命周期。在 server/proactive-candidates.mjs 实现受限发现、一次只读查证、证据卡和基于用户决定的晋升，写入已有工作的身份体系。先测试未授权来源、重复提交及旧卡重放，再实现并复测。
2. 常驻规则。在 server/wake-rules.mjs 实现明确授权的时间、状态和事件规则，持久化发生记录与执行意图。以可控时钟覆盖漏触发、重复事件、暂停竞争、日历和复核回路，复用现有队列。保持已登记规则跨重启可见。
3. 手机界面。通过已有 history/chat 接口在原消息上渲染候选和规则卡，决策携带对象 ID 和版本。验证重试、登录态、不同工作与重复渲染。
4. 总控接线与运行。接入个人服务、模型动作校验、已有工作再唤醒及队列事实。测试从聊天到首次批准、直至形成原工作卡，检查阶段暂停优先于唤醒。执行全套回归，备份现有服务与数据库，部署并验证手机应用。
