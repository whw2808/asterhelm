# 跨设备接续同一件工作

从手机点一个桌面会话的「接着聊」开始，连续几轮改动都属于同一件工作。桌面会话重新进入视野时，用户能读到一条有来源的简短摘要，随后输入「继续」即可按最新决定推进。其他 Agent 可为同一件工作执行子任务。桌面推进的结果也要回到手机原对话。

## 工作、参与者和事实

由总控保存稳定的工作编号。具体会话用设备、连接器和会话编号标识。选择、退出和切换在手机上可见。派单沿用已有任务编号、工作目录和权限。工作日志保留用户的新要求、任务的阶段或结果、绑定桌面会话的新回复及其来源。多次收到同一事件或重启均应保持幂等。仅将同一工作内需要的内容发给关联端。摘要引用已有结果或产物位置，并区分已完成、在执行、已请求暂停和已确认暂停。

## 桌面投递

把同批变化合并为一条「星舵 · 工作更新」，包括手机改动、相关 Agent 的进度与下一步。投递和读取独立记账。只有原线程的可见历史或客户端提供的等价回执可作为显示依据。空闲线程可以接收更新，正在生成的线程在回合边界补齐。重连按每个参与者的游标对账。同步消息附来源与事件标识，回流时排除自身产生的消息；普通桌面新回复应进入手机聊天。

Codex 适配器使用公开的客户端能力。先在虚构会话验证可见历史、模型上下文、回合副作用和去重。仅注入模型上下文无法证明原生 UI 显示，下一次输入时才执行的钩子也无法单独满足到达时可见。禁止直接写 Codex 的内部数据库。缺少可验证的能力时显示待送达，并保留待投递事件。后续可以对接其他具备同等能力的 Agent。总控统一负责路由，收到摘要本身不应执行用户的任务。

## 方案选择

选择按工作记录变化并向其关联端投递。全量镜像双方聊天会传播无关内容，同一件工作由多个 Agent 协作时也更容易重复执行。纯输入钩子适合补充上下文，但无法达到用户发言前已见到更新的目标。工作编号与桌面适配器独立演进，现有用户无需迁移历史会话或改动原有授权。

## 验收

用虚构工作在手机连续修改两次范围并取得一个 Agent 的阶段进展，在同一桌面会话内、发言前看到摘要。桌面只发「继续」，检查是否沿用新的范围和已有成果。回到同一手机对话检查真实桌面结果、任务数量和来源。再覆盖离线重连、重复投递、两个不同工作以及正在运行的回合。分别记录自动化用例、真机操作和原生界面的证据。

## 当前 Codex 客户端的实现选择

用户接受一次只确认收悉的模型回合。常驻连接器调用官方 `codex queue` 向原线程排队，原客户端自行取走。只针对已关联、可见、空闲的会话投递。用本地持久化记录处理断线与重启；原线程出现匹配的摘要和收悉答复，且整个回合没有工具活动，手机才显示已送达。继续工作仍需用户发言。每批摘要会使用一次该会话配置的模型。

标准桌面客户端在测试版本中没有提供无需启动模型的可见消息接口。注入模型历史、添加附件和恢复钩子的试验都未产生用户发言前的可见聊天消息。兼容客户端可额外接入静默写入器。标准队列模式保留 Codex 原有工具权限，提供受信任钩子对已登记的回执回合限制本地工具，并独立校验可见历史。

连接器每次入队前按原会话的工作目录向 Codex 核对三项钩子的命令、事件、启用与信任状态。默认在保护可用时才入队。新会话无需先执行工具。钩子的本地工具覆盖范围取决于 Codex 客户端。

## 真机往返记录

在 Android 上关联一条桌面测试会话，用虚构的图书展分两轮修改范围和纸本目录标题，请另一台 Linux 设备的 Agent 核对宣传标签。连接器向原会话自动投递简报，Codex 回复「星舵 · 已收悉。」。核对原生回合记录，回执中没有工具调用。

在原桌面会话只输入「继续」，Codex 答出纸本目录标题 CEDAR、ORCHID 有 6 个字母，以及电子展区仍暂停。随后在 Android 真机的原工作对话内读到带桌面来源的同一条回复。此次往返验证了桌面客户端接续与 Linux Agent 协作，Linux 本机窗口接收简报另需单独验收。
